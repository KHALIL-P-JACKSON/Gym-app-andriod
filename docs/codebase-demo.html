Where to make a change

Change a screen

Compose functions receive state and callbacks; previews use pure sample fixtures.

presentation/composables/screens/WorkoutScreen.kt

Change validation or weight units

DraftSet parses input, records its entry unit and exposes isValid. Persisted weight is always pounds.

domain/model/Models.kt

Change saving and ordering

WorkoutService builds valid models. The ViewModel coordinates domain work and storage.

domain/service/WorkoutService.kt

Change storage

Room entities, foreign keys and DAO queries live in the data layer. Evolve the schema with a migration.

data/local/TrackerDatabase.kt

Change strength calculations

Per-workout performance, record comparison and local-day streak live in ProgressCalculator.

domain/service/ProgressCalculator.kt

Change preferences

The Settings model is in domain; DataStoreSettingsRepository persists changes and emits a Flow.

Run the real Kotlin demonstration

Open the repository in Android Studio, then run this command from its root. JDK 17 and Android SDK 35 are required; no emulator is needed for this domain demo.

./gradlew testDebugUnitTest --tests 'com.gymtracker.android.demo.CodebaseDemoTest' --info --rerun-tasks

The test prints each checkpoint and calls WorkoutService, DraftSet, ProgressCalculator and CsvExporter. Room persistence and Compose input are covered by the existing device tests.

Open this single file locally; no server or external assets are required. Source links open GitHub. See docs/CODEBASE_DEMO.md for the startup flow, debugger stops, previews and device-test commands.
